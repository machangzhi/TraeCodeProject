## 分析与学习笔记

1. **Embedding 是语义压缩**：把任意长度文本映射到固定维度（384）的稠密向量，向量的每一维捕捉某种语义特征。模型在预训练时学到了"Vue2"和"Vue3"经常出现在相似上下文，所以它们的向量方向接近。
2. **余弦相似度 vs 欧氏距离**：向量已 L2 归一化时，余弦相似度 = 点积，大小只取决于方向夹角，不受向量长度影响。这是语义检索的标准做法。
3. **缓存是 embedding 的基本操作**：同一段文本的向量是确定的，不重复计算能省大量时间和（API 场景下的）费用。生产环境应该用 Redis/磁盘缓存。
4. **本地模型的取舍**：all-MiniLM-L6-v2 是英文为主的模型，中文语义靠字符级特征捕捉，效果不如中文专用模型（如 bge-small-zh）。当前够用，后续如需更好中文效果可换模型。

## 概念卡片

- **Embedding**：将文本（或其他数据）映射为固定维度稠密向量的过程，向量捕捉语义信息。
- **向量空间**：所有 embedding 构成的高维空间，语义相近的文本在空间中距离更近。
- **余弦相似度**：两个向量夹角的余弦值，范围 [-1, 1]，值越大越相似；归一化后等于点积。
- **L2 归一化**：将向量缩放为单位长度（各维度平方和=1），使余弦相似度退化为点积。
- **Mean Pooling**：将 token 级向量取平均得到句子级向量的方法（transformers.js 支持 `pooling: "mean"`）。

## 面试题

### Q1：为什么语义相近的文本向量距离通常更近？
A：因为 embedding 模型在预训练时通过海量语料学习了"语义相近的词经常出现在相似上下文"这一规律。训练目标（如对比学习、掩码语言模型）会把同上下文的词向量拉近、不同上下文的推远。最终句子向量继承了这种性质："Vue2"和"Vue3"都出现在前端组件开发的上下文，所以向量夹角小、相似度高（0.72）；而"Vue2"和"北京天气"上下文完全不同，相似度仅 0.11。

### Q2：为什么要对 embedding 向量做 L2 归一化？
A：归一化后所有向量长度为 1，余弦相似度（cosθ = a·b / |a||b|）退化为点积（a·b），计算更快。更重要的是，归一化消除了向量长度差异的影响——长度可能受文本长度、词频等无关因素影响，而归一化后只保留方向信息，更纯粹地反映语义相似度。

### Q3：embedding 为什么需要缓存？
A：因为同一段文本的 embedding 是确定性的（模型权重不变时），重复计算纯粹浪费。在 API 场景下重复 embedding 会产生费用；在本地模型场景下重复计算浪费时间。缓存策略：以文本为 key，向量为 value，存磁盘或 Redis。生产环境还可做批量去重——先查缓存，只 embed 未命中的文本。
