# Day 45：Similarity Threshold —— 用阈值拦住"无关内容"

> 日期：2026-10-14
> 主题：给检索加相似度阈值（distance = 1 - cosine），低于/高于阈值的召回如何处理；阈值与 TopK 的分工
> 实验脚本：[day45-similarity-threshold.ts](file:///d:/TraeCodeProject/ai-agent-learning/01-ai-chat/server/src/experiments/day45-similarity-threshold.ts)

## 实验设计

唯一变量是 **threshold（相似度阈值）**，测试集固定复用 Day 43/44 的 7 个用例，TopK 固定为 Day 44 得出的甜点值 **K=5**，RAG 链路代码只在"检索后多一道阈值过滤"上做增量。

- **Part A 阈值扫描（零成本，确定性）**：不调 LLM，纯用距离做两件事——
  - A-1 **距离分布对照**：每个用例的"gold 最近距离" vs "最近非 gold 距离"，暴露两者是否重叠；
  - A-2 **阈值扫描**：对 T ∈ {0.40…0.80} 逐档统计"保住 gold 的用例数 / 平均保留 chunk 数 / 平均噪声数 / 库外用例 C7 是否被拦"。
- **Part B 真实对比（LLM）**：两档配置（无阈值 vs threshold=0.7），同 K=5，逐用例真实生成 + 判分，记录 `matched`（是否短路拒答，即省下的 LLM 调用）。

实现口径：`distance = 1 - cosine`，**阈值是 distance 上限**（distance ≤ threshold 才算"够格"）；过滤后一条不剩则直接短路拒答（`matched=false`，不调 LLM）。

## 分析与学习笔记

### 1. 阈值买到的唯一东西是"库外问题的零成本拒答"，代价是误杀两个弱匹配有答案的用例

Part B 一进一出算得很清楚：threshold=0.7 唯一省下的 LLM 调用是 **C7**（库外天气问题，最近距离 0.703 > 0.7 → `matched=false` 短路，省 1 次调用 ≈468 prompt tokens）；代价是 **C1、C6 从 ✅ 变 ❌**，因为它们"有答案但 gold 排得远"（0.800 / 0.752 均被 0.7 一刀切掉）。**7/7 → 5/7，净亏。**

尤其讽刺的是 **C1 并没有因为阈值而省钱**：它的噪声 chunk 距离 0.554 仍低于 0.7，所以 `matched` 照样为 true、照样调了 LLM，只是把"含答案的 5 段上下文"削成了"纯噪声 2 段上下文"——阈值在这里**没省成本、只降低了答案质量**。这也说明"短路省成本"只在"整批召回都超阈值"时才成立。

### 2. 根本原因：gold 与噪声的距离分布重叠，阈值不是排序问题的解药

Part A-1 给出铁证：C1 gold 最近距离 **0.800 > 噪声 0.554**，C6 gold **0.752 > 噪声 0.579**。也就是说这两道题的**正确答案天然排在无关内容后面**（Day 43 已定性为"缺实体锚点的中文查询在英文 embedding 下排序崩塌"）。**阈值是"按距离划一条水平线"，而排序病是"正确答案被压在噪声下面"——水平切一刀治不了垂直的排序错位。** 阈值只擅长处理"整批都远"（库外问题），对"远的是 gold、近的是噪声"完全无能为力。

想让阈值既保 gold 又拦噪声，需要 **0.703（噪声）< T < 0.752（最近 gold）** 的窗口——但 C7 的噪声 0.703 本身就高于部分库内 gold（如 C2 0.391 / C4 0.382），**库外噪声的"远"和库内有答案内容的"远"根本不是一个量级，无法用单一阈值区分**。这是 Day 43 排序崩溃的直接延伸结论。

### 3. 阈值窗口极窄且脆弱，0.7 这个值本身是拍脑袋

C7 最近距离 0.703，阈值 0.70 刚好拦、0.75 就漏；而 C1 gold 0.800、C6 gold 0.752 都在 0.1 的邻域内。**"有效阈值"只剩 0.70 这一个点附近**，稍微调松一档（0.75）库外就漏、稍微调紧一档就多误杀。用一个**全局固定常量**去切一个由 embedding 质量决定的、随 query 浮动很宽的分布，本质上是在硬编码一个不存在的分界线。**结论：阈值应该是"防明显无关"的下限兜底，不是"保证正确性"的主力，且取值必须用真实分布标定，不能抄个 0.7 就上。**

### 4. threshold 与 topK 是两道正交的闸，别用阈值去补 topK 的锅

- **TopK 管"最多取几条"**：K=5 时 C1 的 gold 排第 5 位，刚好被捞进来（无阈值 ✅）；这说明 K 不够会漏，K 够就漏不掉。
- **Threshold 管"够不够格留下"**：它只会**再往下砍**，永远无法把排在第 5 位的 gold 提到前面。

所以当"gold 排位靠后"时：加阈值只会让它更早被砍掉（C1/C6 就是这样），**正确动作是调大 K 或上 Rerank（Day 46）**。两者配合的正确姿势是：**K 给足召回上限 → 阈值只砍明显无关的尾巴**，而不是指望阈值来"精选"。

### 5. 一个反直觉点：库外问题不设阈值也能答对，阈值只是让它更便宜、更可信

无阈值时 **C7 也判 ✅**——模型看着满屏前端文档，自己说出了"参考资料均与天气无关，不包含任何天气信息"，**拒答是模型自己完成的**。这带来两个判断：

- 阈值的价值不在"让模型答对"，而在**"根本不给模型犯错的上下文"**——零成本、零延迟、拒答措辞由系统保证（不依赖模型临时发挥）；
- 但反过来也说明：**在没有阈值时，一个"懂拒答"的模型已经能兜住库外问题**，阈值是"锦上添花的成本优化"，不是"雪中送炭的正确性修复"。

### 6. `matched` 字段是阈值功能的必要可观测面

短路路径返回 `matched=false`，与"调了 LLM 但模型自己拒答"（`matched=true`）在返回值上可区分。没有这个字段，监控里根本分不清"系统没找到"和"模型不想答"——**这正是 Day 43 那个"拒答把检索失败伪装成合规拒答"陷阱的解药**：短路拒答可统计、可归因，而模型自发的拒答不可控。Day 49 建评测集时应把 `matched=false` 的比例单独作为一条监控指标。

### 7. 实跑前的预判被数据部分修正

预判是"阈值主要让库外问题短路拒答，代价是牺牲 C1/C6"——**这部分被证实**。但有一个细节是跑出来才看清的：**C1 在阈值下并没有省下调用**（噪声距离 0.554 低于 0.7，仍 `matched=true`），所以"阈值 = 省成本"这个直觉在小库上并不成立——省成本的前提是"整批召回都超阈值"，而单加阈值经常只砍掉 gold、留下噪声。这提醒：**阈值省的调用数必须实测，不能按"砍掉了 n 条"倒推。**

## 概念卡片

- **Similarity Threshold（相似度阈值）**：给召回距离设一条上限（distance ≤ threshold 才保留），用于在 TopK 之外再加一道"够不够格"的闸。
- **距离 vs 相似度**：`distance = 1 - cosine`；距离越小越相关。面试里要能说清"阈值是距离上限"还是"相似度下限"，两者方向相反、极易搞反。
- **短路拒答（Short-circuit Refusal）**：阈值过滤后一条不剩时直接返回拒答、不调 LLM；用 `matched=false` 与"模型自发拒答"区分开，省成本且拒答可控。
- **距离分布重叠（Distance Distribution Overlap）**：gold 与噪声的距离区间彼此交叠，导致不存在单一阈值能同时"保正确、拦无关"；是决定"阈值能否当主力"的关键判据。
- **阈值标定（Threshold Calibration）**：用真实用例的 gold/噪声距离分布来选阈值，而不是套用经验常量（如 0.7）；必须绑定知识库与 embedding 模型重测。

## 面试题

### Q1：RAG 里加了相似度阈值，是不是就能保证不再召回无关内容？
A：不能，本实验是反例。Part A-1 显示 C1、C6 的 **gold 最近距离（0.800 / 0.752）比它们的最近非 gold（0.554 / 0.579）更远**——正确答案天然排在噪声后面。想保住这 6 个用例的 gold，阈值得放到 **0.80**，可此时库外的 C7（最近噪声 0.703）照样进上下文；想拦住 C7（阈值 ≤0.70），就必然丢掉 C1/C6。**可用阈值区间是空集**，因为"排序错位"是纵向问题，水平切一刀的阈值治不了。真正的解药是 Rerank（重排）。

### Q2：阈值和 TopK 是一回事吗？该用哪个来解决"召回不到答案"？
A：不是一回事，方向相反。**TopK 管"最多取几条"，是向上放宽**；**阈值管"够不够格留下"，是向下收紧**。C1 的 gold 排在召回第 5 位、靠 K=5 刚好捞进来（无阈值 ✅）；一旦加阈值 0.7，这条排在第 5 位的 gold 反而被砍掉，C1 变 ❌。所以"排位靠后"要靠**调大 K 或上 Rerank** 救，**阈值不仅救不了、还会让它更早出局**。正确分工是：K 给足召回上限，阈值只砍明显无关（如库外的 C7）的尾巴。

### Q3：既然无阈值时 C7 也答对了，那阈值到底买到了什么？
A：买到的是**"零成本 + 拒答可控"**，不是"答对"。无阈值时 C7 判 ✅ 是模型自己看着满屏前端文档说出"参考资料均与天气无关"——拒答质量取决于模型当场发挥、且照样花了 1 次 LLM 调用（约 468 prompt tokens）；加 threshold=0.7 后 C7 走 `matched=false` 短路，**不调 LLM、拒答措辞由系统保证**。代价是同一阈值误杀了 C1/C6 两个"有答案但 gold 远"的用例（7/7 → 5/7）。所以阈值在本库是**净亏**：它擅长处理"整批都远"的库外问题，不擅长处理"远的是答案、近的是噪声"的库内弱匹配问题。
