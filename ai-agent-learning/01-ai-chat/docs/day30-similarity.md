## 分析与学习笔记

1. **核心目标达成**：Vue2-Vue3 (0.66) > Vue2-React (0.26)，证明语义相近的文本在向量空间中确实更近。这是 embedding 的核心价值。
2. **两种度量的关系**：向量归一化后，`Euclidean² = 2 - 2×Cosine`。所以 Cosine 越大 ↔ Euclidean 越小，排序完全一致。实验数据完全吻合（如 D1-D2: cos=0.6623, euc=0.8218 → √(2-2×0.6623)=√0.6754=0.8218）。
3. **Top K 偏差的原因**：Q1 和 Q2 的 Top1 错误，根因是 **all-MiniLM-L6-v2 是英文预训练模型**，对中文细粒度语义区分能力有限：
   - Q1「Vue3 的响应式原理」与 D5「美食做法」得分 0.501，仅比 D2 的 0.500 高 0.001——本质是模型对中文「响应式」「做法」等词的语义编码不够精确。
   - Q2「做菜」匹配到 D6「足球」0.594，可能是因为两者都属于"日常生活"范畴，模型没有区分"烹饪"和"体育"。
4. **改进方向**：后续 RAG 阶段应考虑
   - 换中文专用 embedding 模型（如 `bge-small-zh`、`m3e-base`）
   - 加 Rerank 阶段（Day 46）重排 Top 20
   - Query Rewrite（Day 47）改写用户问题

## 概念卡片

- **Cosine Similarity**：两个向量夹角的余弦值，范围 [-1, 1]，衡量方向相似性，不受向量长度影响。
- **Euclidean Distance**：向量空间中两点的直线距离，√Σ(ai-bi)²，范围 [0, ∞)，衡量绝对差异。
- **Top K**：从候选集中按相似度取前 K 个，是向量检索的基本操作。
- **归一化**：将向量缩放为单位长度，使 Cosine 退化为点积，消除长度差异。
- **Embedding 模型语言适配**：英文预训练模型对中文语义编码有限，中文场景应选用中文专用模型。

## 面试题

### Q1：Cosine Similarity 和 Euclidean Distance 有什么关系？
A：当向量都做了 L2 归一化（长度为 1）后，两者满足 `Euclidean² = 2 - 2×Cosine`。因此归一化后 Cosine 越大等价于 Euclidean 越小，排序完全一致。语义检索中通常先归一化再用 Cosine（=点积），计算更简单。实验中 D1-D2 的 cos=0.6623、euc=0.8218，验证了 √(2-2×0.6623)=0.8218。

### Q2：为什么语义检索通常用 Cosine 而不是 Euclidean？
A：因为 embedding 向量的长度可能受文本长度、词频等无关因素影响，而 Cosine 只看方向夹角，不受长度影响。更重要的是，大多数 embedding 模型在训练时或使用时会做 L2 归一化，此时 Cosine 直接等于点积，计算最快。Euclidean 适合比较绝对值有意义的场景（如坐标、数值特征），不适合语义空间。

### Q3：你的 Top K 检索有 2/3 没命中，这说明什么？
A：说明当前 embedding 模型（all-MiniLM-L6-v2，英文预训练）对中文细粒度语义的区分能力不足。Q1「Vue3 响应式」与 D2「Vue3 规范」的得分仅比 D5「美食」高 0.001，几乎无法区分。这不是相似度度量的问题，而是模型的问题。解决方案：换中文专用模型（bge-small-zh）、加 Rerank、或做 Query Rewrite。
